# Post-v5.4 Hygiene — Doctor Cleanup, Bootstrap Trim, Owner Allowlist e Quarentena de Backups Corrompidos

## TL;DR

Sessão de hygiene 6h após o upgrade 5.4 estabilizar. `openclaw doctor` flagou 8 itens; resolvidos 7 (1 descartado por escolha). Aprendizados que valem replicar:

1. **`plugins.bundledDiscovery: "compat"`** — novo setting v5.4 que aparece quando `plugins.allow` é restritivo. Default ausente = inconsistência. `doctor --fix` migra pra `compat` (preserva descoberta legacy de bundled providers).
2. **`commands.ownerAllowFrom`** — sem essa allowlist, ninguém roda `/diagnostics`, `/config`, `/export-trajectory` ou aprova `exec` dangerous. Default não vem setado.
3. **Bootstrap files (MEMORY.md/TOOLS.md) trim** — quando passam o limite (12k/file, 60k total injected), doctor avisa truncamento. Estratégia: mover seções verbosas pra topic files dedicados.
4. **"Memory artifact malformed" do doctor era falso alarme** — vinha de **backups SQLite antigos** com `chunks_fts` vtable obsoleta, não dos DBs ativos. Quarentena dos backups silencia o warning.
5. **Sessions cleanup de transcripts órfãos** — 128 `.jsonl` + 292 `.trajectory.jsonl` não-referenciados em `sessions.json`. Rename → `.deleted.<ts>` + `cleanup --enforce --fix-missing` removeu 8 entries stale do store.
6. **`openclaw doctor --fix` desabilita skills com missing requirements automaticamente** — 33 skills macOS-only desabilitadas em VPS Linux (`apple-notes`, `imsg`, `things-mac`, `bear-notes`, etc).
7. **Drift documental descoberto:** `TOOLS.md` ainda dizia que `openclaw-gateway` rodava como `systemctl --user` — mas migrou pra system-level (`/etc/systemd/system/openclaw-gateway.service`) em algum upgrade anterior sem o doc acompanhar.

Estado pós-hygiene: doctor limpo (só warning informativo de `bundledDiscovery=compat` por escolha), zero issues críticas, ~905M de disco recuperado (144M sessions + 761M de backups que ficaram quarentenados sem deletar).

## Detalhes que valem (per item)

### 1. `plugins.bundledDiscovery: "compat"` — release notes v5.4 confirma

Doctor original output:
```
- plugins.allow: plugins.allow now gates bundled provider discovery by
  default; run "openclaw doctor --fix" to preserve legacy bundled
  provider compatibility as plugins.bundledDiscovery="compat", or set
  plugins.bundledDiscovery="allowlist" to keep the stricter behavior.
```

**3 estados possíveis:**
- `"compat"` — bundled providers descobertos automaticamente (legacy behavior; o default que `doctor --fix` aplica em configs com `plugins.allow` restritivo)
- `"allowlist"` — bundled providers só aparecem se listados em `plugins.allow` (stricter)
- ausente — modo legacy implícito (= comportamento antigo, mas doctor reclama da inconsistência)

**Decisão recomendada:** `compat` por default em upgrades. Apertar pra `allowlist` exige auditoria do que está sendo permitido (zero risco de comportamento, baixo benefício de segurança em VPS single-user).

### 2. `commands.ownerAllowFrom` — gap de segurança silencioso

Schema v5.4: array de strings `"<canal>:<user_id>"`. Sem isso:
- `/diagnostics`, `/config`, `/export-trajectory` não funcionam
- `exec` approval prompts não tem ninguém autorizado a aprovar
- DM pairing apenas autoriza interação, não privilégios

**Como descobrir o user_id sem expor pairing files:**
- **Discord:** já está em `channels.discord.guilds.<gid>.users[]` ou `.channels.<cid>.users[]` no `openclaw.json`
- **Slack:** workspace user ID (formato `U[A-Z0-9]+`) — se já documentado nos próprios docs, reutilizar
- **Telegram:** `/whoami` ao bot, ou `@userinfobot`, ou ler `credentials/telegram-pairing.json` (somente o `user_id`, jamais o token)

Comando:
```bash
openclaw config set commands.ownerAllowFrom \
  '["discord:<USER_ID>","slack:<USER_ID>"]'
```

Restart gateway pra aplicar.

### 3. Bootstrap files trim — estratégia replicável

`MEMORY.md` e `TOOLS.md` no `~/.openclaw/workspace/` são injetados em **toda inicialização de turno** dos agentes. Limites default v5.4: 12.000 chars/file, 60.000 total. Acima disso, **truncados silenciosamente** — perde-se bottom contents.

**Estratégia comprovada nesta sessão:**

1. **Mapear seções por tamanho** (awk one-liner):
   ```bash
   awk '/^## /{if(s)print l, s; l=$0; s=0; next} {s+=length+1} END{if(s)print l,s}' MEMORY.md \
     | sort -k2 -nr | head -10
   ```
2. **Mover seções > 1k pra topic files** dedicados em `~/.openclaw/workspace/memory/<topic>.md`
3. **MEMORY.md vira índice puro:** apenas regras absolutas + tabela de topic files + ciclo de memória + time de agentes
4. **Adicionar header em cada topic file** apontando que veio do trim (auditoria/recuperação fácil)

**Resultados desta sessão:**
- MEMORY.md: 14,544b → 2,725b (-81%)
- TOOLS.md: 12,158b → 7,482b (-38%)
- Conteúdo total preservado (nada perdido — só redistribuído)

**Anti-padrão:** bumpar `agents.defaults.bootstrapMaxChars` em vez de fazer o trim. Isso só adia o problema e gasta tokens em todo turno.

### 4. "Memory artifact malformed" — distinguir backup de DB ativo

Doctor v5.4 introduziu varredura de SQLite. Se algum `.db` no scope retornar `database disk image is malformed` ou `chunks_fts vtable failed`, doctor reporta:
```
Memory artifact repair could not be completed: database disk image is malformed
```

**Mas a varredura inclui backups antigos** — DBs criados antes de migrações de schema podem ter vtables FTS5 obsoletas (caso clássico: backups pre-v9/v10 do `nox-mem` ou `graph-memory_<date>.db` antigos). Esses backups **estão de fato corrompidos no schema atual**, mas não afetam runtime.

**Diagnóstico correto:**
```bash
for db in $(find /root/.openclaw -name '*.db' -o -name '*.sqlite'); do
  r=$(sqlite3 "$db" 'PRAGMA integrity_check;' 2>&1 | head -1)
  [[ "$r" != "ok" ]] && echo "BAD: $db -> $r"
done
```

**Triagem:**
- DB **ativo** corrompido = ação imediata (restore do último backup íntegro)
- DB **backup antigo** corrompido = quarentena (rename `.corrupt-<ts>`) ou aceitar warning
- **Não deletar backups corrompidos imediatamente** — eles ainda podem ter dados parciais recuperáveis via `sqlite3 X.db ".recover"` se algum dia precisar

Quarentena silenciou o warning sem perder opção de recovery.

### 5. Sessions cleanup — orphan transcripts vs missing entries

Dois problemas distintos no doctor:

**A. "Found N orphan transcript files":** arquivos `.jsonl` em `~/.openclaw/agents/<agent>/sessions/` que não estão referenciados em `sessions.json`. Doctor diz "Doctor can archive them safely by renaming each file to *.deleted.<timestamp>" mas **NÃO faz isso no `--fix`**. Tem que ser manual.

**B. "N/M recent sessions are missing transcripts":** entries em `sessions.json` cujo `sessionFile` não existe. Resolução:
```bash
openclaw sessions cleanup --enforce --fix-missing
```

**Script Python pra archive de orphans (descobrindo apenas os realmente órfãos):**
```python
import json, os, glob
STORE = "~/.openclaw/agents/main/sessions/sessions.json"
SESS_DIR = "~/.openclaw/agents/main/sessions"
TS = "20260505"
data = json.load(open(STORE))
referenced = set()
def walk(o):
    if isinstance(o, dict):
        for k, v in o.items():
            if k in ("sessionFile", "transcriptFile", "file") and isinstance(v, str) and v.endswith(".jsonl"):
                referenced.add(os.path.basename(v))
            walk(v)
    elif isinstance(o, list):
        for x in o: walk(x)
walk(data)
referenced_traj = {f.replace(".jsonl",".trajectory.jsonl") for f in referenced}
for p in glob.glob(os.path.join(SESS_DIR, "*.jsonl")):
    base = os.path.basename(p)
    is_traj = base.endswith(".trajectory.jsonl")
    is_orphan = (base not in referenced_traj) if is_traj else (base not in referenced)
    if is_orphan: os.rename(p, p + ".deleted." + TS)
```

Cuidado: trajectory `.jsonl` files são linked à transcripts via filename twin (`X.jsonl` ↔ `X.trajectory.jsonl`). O script considera trajectory orphan se a transcript-twin NÃO está referenciada em `sessions.json`.

### 6. Doctor --fix desabilita skills com missing requirements

VPS Linux acabou com 33 skills disabled por faltar binário/OS:
```
- Disabled apple-notes (os: darwin)
- Disabled imsg (bins: imsg; os: darwin)
- Disabled things-mac (os: darwin)
- Disabled blucli (bins: blu)
- Disabled camsnap (bins: camsnap)
- ... (28 more)
```

Boa limpeza — esses warnings poluíam todo `doctor` run. Reversível: re-enable em `~/.openclaw/openclaw.json` se um dia for instalar o binário (`skills.entries.<id>.enabled: true`).

### 7. Drift documental — gateway systemd scope

`TOOLS.md` na sessão anterior afirmava:
```
- Serviço legítimo: /root/.config/systemd/user/openclaw-gateway.service
- Diagnóstico correto: systemctl --user status openclaw-gateway
- ❌ NÃO criar ou editar /etc/systemd/system/openclaw-gateway.service
```

Mas `openclaw status` mostrou claramente:
```
Gateway service: systemd user not installed
```

E `systemctl list-units` confirma o serviço em `/etc/systemd/system/openclaw-gateway.service` com drop-ins (`circuit-breaker.conf`, `override.conf`).

**Causa provável:** algum upgrade migrou pra system-level (talvez `--enable-restart-policy` ou similar) sem atualizar `TOOLS.md`. Doc drift silencioso por semanas/meses.

**Lição:** quando bootstrap files contêm operações de runtime, validar contra realidade do sistema durante revisões periódicas. Trim foi gatilho útil pra pegar isso.
