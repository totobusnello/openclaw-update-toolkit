# OpenClaw v2026.5.2 Upgrade — 3 Pitfalls Não Documentados

## TL;DR

Upgrade `2026.4.29 → 2026.5.2` (pulou 4 releases intermediárias). Multi-agent review prévio (architect+code-reviewer+researcher) identificou riscos conhecidos via release notes e plugin externalization. Mas 3 pitfalls **não documentados publicamente** causaram 2 fails sequenciais antes do swap completar:

1. **Web search provider validation strict (5.2 NEW)**: gateway recusa boot se `tools.web.search.provider` aponta pra plugin não-instalado/disabled. Config-zumbi tolerada na 4.29 vira blocker na 5.2.
2. **`chattr +i` no node_modules global colide com `npm install -g`**: arquivos imutáveis (do emoji patch — regra 2.1 nossa, não upstream) bloqueiam `rm` durante install, deixando binário openclaw QUEBRADO no meio.
3. **`openclaw plugins install` é destrutivo entre packages scoped `@openclaw/*`**: cada install scoped REMOVE o anterior do `node_modules/@openclaw/`. Workaround: `npm install` direto.

**Recovery total:** ~5min downtime real do gateway (entre `npm install -g` falhar e recovery manual). Sem perda de dados, sem perda de mensagens (queue persistente). Final: gateway estável, 11 plugins loaded, 4 canais (slack/telegram bundled + discord/whatsapp via `@openclaw/*`).

## Pitfall 1: Web search provider validation strict

### Sintoma
Phase 1 staging boot falhou imediatamente:
```
Gateway failed to start: Error: Invalid config at /root/.openclaw/openclaw.json.
tools.web.search.provider: web_search provider is not available: brave
(install or enable plugin "brave", then run openclaw doctor --fix)
```

### Causa raiz
Na v.5.2 o gateway introduziu **validação estrita** de `tools.web.search.provider` contra o plugin set ATIVO. Release notes mencionou só de relance (#53092 — *"validate configured web-search providers... against the active plugin set at config load"*). Configs antigas onde o provider apontado estava `enabled:false` (config-zumbi) eram toleradas na 4.29; viram blocker na 5.2.

No nosso caso, `tools.web.search.provider = "brave"` mas plugin `brave` estava `enabled:false, status:disabled` desde 4.29 — não usávamos web search ativamente. Ninguém percebeu o mismatch antes.

Adicionalmente, `brave` foi **externalized** na 5.2 (não bundled) — então mesmo `openclaw plugins enable brave` não funcionaria sem `npm install` separado.

### Fix (zero downtime)
```bash
cp /root/.openclaw/openclaw.json /root/.openclaw/openclaw.json.bak-pre-websearch-fix-$(date +%Y%m%d-%H%M%S)
openclaw config set tools.web.search.provider duckduckgo  # bundled na 5.2, zero-config
openclaw config validate  # → "Config valid"
```

Providers seguros bundled na 5.2: `duckduckgo`, `searxng`, `exa`, `firecrawl`, `tavily`, `kimi-coding`, `web-readability`, `webhooks`.

### Generalização
Antes de QUALQUER upgrade do OpenClaw, fazer config audit:
- Validar que TODA referência em `tools.*.provider`, `plugins.entries.*`, `plugins.allow` aponta pra plugin presente+enabled na versão alvo
- Particularmente: `tools.web.search.provider`, `tools.image.understand.provider`, `tools.audio.transcribe.provider`
- Versões futuras podem expandir validação strict pra outros campos

## Pitfall 2: `chattr +i` colide com `npm install -g`

### Sintoma
Phase 3b atomic swap falhou no meio de `npm install -g openclaw@2026.5.2`:
```
rm: cannot remove '/usr/lib/node_modules/openclaw/dist/status-message-Bwz2ekKl.js':
Operation not permitted
```
Gateway down. `which openclaw` retorna vazio. Restart counter = 5 ("Start request repeated too quickly").

### Causa raiz
Nosso emoji patch (regra 2.1 do CLAUDE.md, aplicado em 2026-05-01) usa `chattr +i` em arquivos `status-message-*.js` dentro de `/root/.openclaw/plugin-runtime-deps/openclaw-*/dist/` E também em `/usr/lib/node_modules/openclaw/dist/` quando o reapply script encontra match. O `chattr +i` é proteção contra invalidação acidental em runtime.

Ao fazer `npm install -g openclaw@<nova-versão>`, o npm tenta `rm` os arquivos antigos antes de extrair os novos. O `chattr +i` impede o `rm` → operação parcial → tree node_modules destruído mas binário não substituído → openclaw quebrado.

### Fix (recovery manual)
```bash
# 1. Remover chattr +i de tudo no global node_modules
find /usr/lib/node_modules/openclaw -type f -exec lsattr {} \; 2>/dev/null \
  | grep "^----i" | awk '{print $NF}' | xargs -r chattr -i

# 2. Reset systemd failure count
systemctl reset-failed openclaw-gateway

# 3. Re-rodar npm install -g (agora vai conseguir)
npm install -g openclaw@<TARGET>
which openclaw && openclaw --version  # confirmar restaurado

# 4. Reapplicar patches + reimutabilizar
bash /root/reapply-monkey-patch.sh
python3 /root/reapply-session-status-emoji-patch.py
chattr +i /root/.claude/.credentials.json /usr/local/bin/openclaw-gateway-wrapper
chattr +i /root/.openclaw/plugin-runtime-deps/openclaw-*/dist/status-message-*.js  # o que tiver "OAuth (Max)"

# 5. Start
systemctl daemon-reload && systemctl start openclaw-gateway
```

### Mitigação permanente
Adicionar passo `[3b.0]` no `upgrade-zero-downtime.sh` ANTES do `npm install -g`:
```bash
echo "[3b.0] Removing chattr +i from /usr/lib/node_modules/openclaw before npm install..."
IMMUTABLE_COUNT=$(find /usr/lib/node_modules/openclaw -type f -exec lsattr {} \; 2>/dev/null | grep -c "^----i" || true)
if [[ "$IMMUTABLE_COUNT" -gt 0 ]]; then
  echo "    found $IMMUTABLE_COUNT immutable file(s) — removing chattr +i"
  find /usr/lib/node_modules/openclaw -type f -exec lsattr {} \; 2>/dev/null \
    | grep "^----i" | awk '{print $NF}' | xargs -r chattr -i
fi
```

## Pitfall 3: `openclaw plugins install` destrutivo entre scoped packages

### Sintoma
Após cutover de externalização (WhatsApp, Discord, etc. saíram do bundled na 5.2), instalar via CLI um por vez:
```bash
openclaw plugins install @openclaw/whatsapp  # OK, whatsapp aparece em plugins list
openclaw plugins install @openclaw/discord   # OK, discord aparece — MAS whatsapp SUMIU
```

### Investigação
- Logs do gateway às 17:59:17 mostraram WhatsApp ATIVO: `[whatsapp] [default] starting provider (<REDACTED-PHONE>)` + `Listening for personal WhatsApp inbound messages`
- Após `openclaw plugins install @openclaw/discord` às 18:01:30, próximo gateway start mostrou 7 plugins SEM whatsapp
- `ls /root/.openclaw/npm/node_modules/@openclaw/` confirmou apenas `discord` (whatsapp removido fisicamente)
- Bug: comando `openclaw plugins install` provavelmente faz `npm install --save-exact` sem preservar deps existentes em `/root/.openclaw/npm/package.json`

### Fix (workaround)
Usar `npm install` direto em `/root/.openclaw/npm/`:
```bash
cd /root/.openclaw/npm
npm install @openclaw/whatsapp @openclaw/discord  # ambos juntos, preserva os 2

# Validar:
ls /root/.openclaw/npm/node_modules/@openclaw/  # deve listar AMBOS

# Plugin pode precisar enable explícito após install:
openclaw plugins enable whatsapp
systemctl restart openclaw-gateway

# Validar carregamento:
openclaw plugins list --json | jq '.plugins[] | select(.id | test("whatsapp|discord")) | {id, enabled, status, origin}'
# Esperado: ambos enabled:true, status:loaded, origin:global
```

### Generalização
- **Pacotes corretos têm scope `@openclaw/*`** — `whatsapp` sem scope no npm é alpha 0.0.5 sem manifest correto; `discord` sem scope é biblioteca de jogo. Vai falhar com `package.json missing openclaw.extensions`.
- **ClawHub alternativa**: `openclaw plugins install clawhub:<X>` quando disponível. Hoje (2026-05-03) ainda não tem todos: `clawhub:whatsapp` retorna "Package not found"; `clawhub:discord` retorna "discord is a skill".
- **Anchor pra sobreviver upgrades futuros**: `/root/.openclaw/npm/package.json` mantém deps `^2026.5.2`. Após upgrade do binário global, basta `cd /root/.openclaw/npm && npm install` pra repuxar.

## Schema mudança não documentada (bonus)

`agentRuntime.id` foi REMOVIDO do schema na 5.2 (não consta na release notes). `openclaw config get agentRuntime.id` retorna "Config path not found". Era invariante I1 dos runbooks RB-11/RB-12; vira N/A. Path canonical funcional substitui:
- `model.primary = anthropic/claude-sonnet-4-6`
- `models.providers.anthropic.{baseUrl, api}`
- `auth-profiles.json` profile `anthropic-max`
- Subprocess CLI Claude continua sendo o backend; conceito de runtime declarativo virou plugin-based.

## Lições gerais para upgrades futuros

1. **Multi-agent review prévio funciona** — architect+code-reviewer+researcher pegou ~7 dos riscos conhecidos. Mas ainda assim 3 pitfalls não-documentados passaram. Lição: NUNCA confiar 100% em release notes; sempre fazer staging real.

2. **Auto-rollback do orquestrador funcionou perfeitamente** no 1º fail (web search) — abortou ANTES do atomic swap real, prod 100% intacta. Validação do design "Phase 1 staging isolado" pago dividendos.

3. **Recovery manual viável** quando 2º fail aconteceu DURANTE o swap — porque o snapshot de rollback (`/usr/lib/node_modules/openclaw.bak-pre-2026.5.2`) estava disponível como fallback ÚLTIMO. Em vez de rollback (volta pra 4.29 e refazer depois), continuamos o swap pra 5.2 — mais rápido.

4. **Pulando 4 releases intermediárias** (4.30/4.31/5.0/5.1 → 5.2) amplifica risco de mudanças cumulativas não-documentadas. Estratégia futura: tentar não pular mais de 2 releases.

5. **Backups múltiplos salvaram**: tar.gz pré-upgrade + sqlite VACUUM dos 6 nox-mem.db + snapshot plugins JSON + inline backups (`*.bak-pre-websearch-fix-*`, `*.bak-pre-stale-cleanup-*`). Em nenhum momento estivemos em risco de perda real.
