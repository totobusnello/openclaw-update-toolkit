## 3 incidentes durante janela (todos resolvidos)

### Incidente 1: `set -e` + `systemctl is-active` aborta Phase 2.4

**Sintoma:** após stop reverso dos services, `systemctl is-active` retorna exit non-zero quando service está inactive (esperado). Mas com `set -e` o script bash inteiro aborta antes de chegar ao npm install.

**Resolução:** resume manual a partir do passo 2.5, removendo `set -e` e usando `2>&1` em is-active. Pesa também `systemctl reset-failed` antes do install (estados `failed` deixados pelo abort não bloqueiam mas confundem).

**Lição:** scripts de upgrade NÃO devem usar `set -e` em blocos com `systemctl is-active` — é um query, não comando. Usar `|| true` ou `set +e`/`set -e` cercando.

### Incidente 2: HTTP 500 transient pós-swap (`ERR_MODULE_NOT_FOUND` referenciando hashes 5.4)

**Sintoma:** primeiro start pós-`npm install`, gateway sobe e responde, mas requests caem em HTTP 500 com `Cannot find module '/usr/lib/node_modules/openclaw/dist/managed-image-attachments-BlVz1LEJ.js'` (hash 5.4 que não existe mais).

**Análise:** hash 5.4 NÃO está em arquivo nenhum do FS (confirmado via grep -rl). dist/ está clean (3750 files = 3749 do 5.6 + 1 .bak nosso). É **state stuck no processo** — V8/Node compile cache mantendo paths resolvidos do estado pre-swap, ou algum module map em memória que não foi rebuilt.

**Resolução:** `systemctl restart openclaw-gateway` (clean state). Pós-restart: 11 plugins enabled, /system/health: 200, zero errors.

**Lição:** **post-`npm install` em prod, sempre fazer um `systemctl restart` adicional do gateway**. O start automático do `systemctl start` pós-install pode pegar caches stale. Restart explícito força fresh state.

### Incidente 3: head-1 chunk split bug (descoberto Phase 0.C, corrigido pre-janela)

**Sintoma:** v5.6 ships 2 arquivos `restart-stale-pids-*.js` (stub 131B + main 20K). Scripts `reapply-gateway-fix.sh` + `check-monkey-patch.sh` selecionavam via `ls ... | head -1`. Em ordem alfabética, o stub `Cf4Rv3_v.js` viria primeiro — reapply patch falha + canary cron emite falso CRITICAL hourly.

**Resolução:** trocar `head -1` por `xargs grep -lF "function cleanStaleGatewayProcessesSync" | head -1` em ambos scripts. Seleciona pelo conteúdo, não ordem alfabética. Backups criados: `.bak-pre-headfix-20260507-141621`. Smoke-test no 5.4 atual confirmou que continua funcionando.

**Lição:** versões recentes do OpenClaw splittam bundles em múltiplos chunks com hash. Scripts que assumem 1 file por nome-padrão são frágeis. Seleção por conteúdo (`grep -lF`) é robusta.

### Incidente 4 (não-blocante): marker mismatch reapply vs canary

**Sintoma:** pós-reapply do monkey-patch no 5.6, `check-monkey-patch.sh` retornou exit=1 ("monkey-patch LOST") apesar do file ter sido patcheado.

**Análise:** mismatch histórico:
- `reapply-gateway-fix.sh` aplica marker `MONKEY-PATCHED 2026-04-20 fix Issue #62028`
- `check-monkey-patch.sh` busca `MONKEY-PATCH: Issue #62028` (legacy, sem hífen + com dois-pontos)

No 5.4 ambos markers coexistiam (alguém aplicou ambos manualmente em algum momento). Reapply só produziu o primeiro no 5.6, e canary procura o segundo → falso CRITICAL.

**Resolução:** alinhar `check-monkey-patch.sh` ao marker que reapply produz: `MONKEY-PATCHED 2026-04-20 fix Issue #62028`. Backup criado: `.bak-marker-fix-20260507-150010`. Sync local mirror feito.

**Lição:** sempre que dois scripts cooperam via marker em arquivo, usar **mesma constante string em ambos** (idealmente extraída pra um source comum, ou pelo menos comentário cruzado).

## Lições estratégicas

1. **Patch releases ainda surpreendem.** v2026.5.6 era "4 fixes corretivos" no release notes — janela real teve 4 incidentes (1 blocker pre-janela + 3 durante). Patch ≠ trivial. **Manter rigor de plan completo mesmo pra patches**.

2. **Scripts cooperantes precisam constantes compartilhadas.** Marker mismatch só apareceu agora porque drift histórico ficou mascarado pela aplicação dupla. **Audit cross-script de strings de coordenação anualmente**.

3. **`set -e` em scripts de upgrade é arma carregada.** Comandos query (`is-active`, `lsattr`) retornam non-zero como sinal, não erro. **Usar `|| true` ou `set +e/-e` ao redor**.

4. **Hash chunked em bundle = sempre seleção por conteúdo.** OpenClaw migrou pra esbuild/rollup chunking. Scripts que assumem 1 file/pattern viram fragile silenciosamente. **Padrão: `xargs grep -lF "<unique-symbol>" | head -1`**.

5. **Restart explícito pós-`npm install`.** Não confiar no `systemctl start` automático que pega caches stale. **Sempre `systemctl restart <service>` extra**.

6. **Salto deliberado de versão é estratégia válida quando release X reverte X-1.** Pulamos 5.5 pq 5.6 reverteu o `doctor --fix` quebrado de 5.5. Padrão repetível: **se release notes usam linguagem "revert", validar baseline + skip a versão broken**.
