# Lesson 2026-05-21 — Upgrade OpenClaw 5.19 → 5.20: 2 regressões + bug user/system service

## Sintoma

`openclaw update` 5.19 → 5.20 reportou success ("Update Result: OK") + "Total time: 93.16s" mas três problemas silenciosos apareceram em sequência:

1. **Gateway continuou na versão antiga** — `gateway status --json` mostrou `cli.version: 2026.5.20` mas `systemctl status` confirmou pid 1868742 (5.19) ainda rodando.
2. **graph-memory desabilitado** — count de plugins caiu 13 → 12; doctor warning `"plugin disabled (not in allowlist) but config is present"`; logs sem extraction lines.
3. **Ruído novo nos logs** — WARN repetidos `"Skipping escaped skill path outside its configured root"` pra cada symlink em `agents/*/skills/<X>`.

## Diagnóstico

### 1. `openclaw update` não restarta system service

`openclaw update` reportou explicitamente:
```
Restarting service...
Gateway: restart skipped (no installed service found).
```

Investigação revelou que o CLI busca **systemd user service** (`systemctl --user list-units`), mas em produção o gateway é **system service** em `/etc/systemd/system/openclaw-gateway.service`. Mesmo bug afeta `openclaw gateway status --json`, que retorna `service.label: "systemd user"` + `runtime.status: "stopped"` mesmo com o gateway system service ativo (pid 1868742, porta 18789 em LISTEN, heartbeats correndo).

NPM package em `/usr/lib/node_modules/openclaw` atualizou pra 5.20, mas processo em memória continuou no 5.19 — discrepância silenciosa que só `systemctl status` ou `ps` revelaria.

### 2. graph-memory derrubado por duas mudanças combinadas

#### 2a. Update tentou substituir source local por ClawHub package quebrado

Output do update incluiu:
```
Resolving clawhub:graph-memory@1.5.8…
Downloading plugin graph-memory@1.5.8 from ClawHub…
Disabled "graph-memory" after plugin update failure; OpenClaw will continue without it.
Failed to update graph-memory: package install requires compiled runtime output for
TypeScript entry ./index.ts: expected ./dist/index.js, ./dist/index.mjs, ./dist/index.cjs
```

O package ClawHub `clawhub:graph-memory@1.5.8` distribui apenas `.ts` source sem `dist/` compilado. Em 5.19 isso ainda funcionava via "TypeScript source fallback for source checkouts and local development paths". Em 5.20 o fallback ainda existe **mas só pra source-checkouts em `extensions/`** — packages ClawHub instalados via `plugins install` exigem `dist/` real.

Felizmente o source-checkout local em `/root/.openclaw/extensions/graph-memory/` permaneceu intacto (dist de May 17, source unchanged Apr 24, `SYNTAX_OK`). Apenas o entry no `openclaw.json` foi marcado `enabled: false`.

#### 2b. Gate novo: `plugins.allow` whitelist

Re-flipar `enabled: true` no entry **não bastou.** Após restart, o warning mudou de `"plugin disabled (disabled in config)"` pra `"plugin disabled (not in allowlist) but config is present"`.

5.20 introduziu `plugins.allow` no `openclaw.json` como gate adicional, parte do novo bundled Policy plugin (release notes: *"CLI/policy: add the bundled Policy plugin for policy-backed channel conformance checks, doctor lint findings, and opt-in workspace repair (#80407)"*). A própria mensagem de erro do `openclaw policy --help` confirmou o mecanismo:
> *"The `openclaw policy` command is unavailable because `plugins.allow` excludes 'policy'. Add 'policy' to `plugins.allow` if you want that bundled plugin CLI surface."*

`plugins.allow` no nosso `openclaw.json` listava 17 plugins pré-upgrade — todos os bundled core e os 2 channels externalized (`discord`, `whatsapp`). **`graph-memory` não estava** porque pré-5.20 não havia esse gate.

### 3. WARN symlink-escape: 5.20 endureceu detection

5.20 endureceu validação de symlink-escape em skill paths. Cada agent tem rootDir `workspace/agents/<id>/skills/`, mas 50 symlinks em `atlas/boris/cipher/forge/lex/nox/skills/<X>` apontam pra `/root/.openclaw/workspace/skills/<X>` — fora do rootDir do agent → WARN.

Investigação confirmou que esses symlinks são **legacy pré-introdução de `skills.load.extraDirs`**. Hoje a config tem:
```json
"skills": {
  "load": {
    "extraDirs": ["/root/.openclaw/workspace/skills"]
  }
}
```
Skills carregam globalmente via `extraDirs` independente de symlinks locais. Prova viva: agent `main` já não tinha symlinks (0 dele) e reportava as mesmas 70 skills eligible no doctor que os outros. `agents.list[<id>]` no config NÃO tem campo `skills` ou `skillScope` per-agent.

## Fix aplicado

### 1. Restart manual do system service

```bash
ssh root@<REDACTED-TAILSCALE-IP> 'systemctl restart openclaw-gateway && sleep 8 && systemctl status openclaw-gateway --no-pager | grep -E "Active|Memory|Main PID"'
```

Pid 1868742 → 2010547, memory 449M (estável), uptime resetado, ExecStartPre `fuser -k 18789/tcp` exitou 1/FAILURE (esperado — nada pra matar, stop foi clean).

### 2. Re-enable graph-memory + adicionar ao allowlist

```bash
# Backup
ssh root@<REDACTED-TAILSCALE-IP> 'cp /root/.openclaw/openclaw.json /root/.openclaw/openclaw.json.bak-pre-graph-mem-reenable-$(date +%Y%m%d-%H%M%S)'

# Flip enabled false -> true
ssh root@<REDACTED-TAILSCALE-IP> 'jq ".plugins.entries[\"graph-memory\"].enabled = true" /root/.openclaw/openclaw.json > /tmp/oc.new && mv /tmp/oc.new /root/.openclaw/openclaw.json'

# Adicionar ao allowlist (idempotente)
ssh root@<REDACTED-TAILSCALE-IP> 'jq "if (.plugins.allow | type) == \"array\" and (.plugins.allow | index(\"graph-memory\")) == null then .plugins.allow += [\"graph-memory\"] else . end" /root/.openclaw/openclaw.json > /tmp/oc.new && mv /tmp/oc.new /root/.openclaw/openclaw.json'

# Restart
ssh root@<REDACTED-TAILSCALE-IP> 'systemctl restart openclaw-gateway'
```

### 3. Deletar symlinks legacy

```bash
# Backup do listing antes
ssh root@<REDACTED-TAILSCALE-IP> 'find /root/.openclaw/workspace/agents/*/skills/ -maxdepth 1 -type l -lname "/root/.openclaw/workspace/skills/*" -printf "%p -> %l\n" > /root/.openclaw/backups/symlinks-removed-$(date +%Y%m%d-%H%M%S).txt'

# Delete com filtro estrito (preserva symlinks pra /usr/local/lib/node_modules/openclaw/skills/<X>)
ssh root@<REDACTED-TAILSCALE-IP> 'find /root/.openclaw/workspace/agents/*/skills/ -maxdepth 1 -type l -lname "/root/.openclaw/workspace/skills/*" -delete'
```

## Causa estrutural (não corrigida nesta sessão)

### 1. `openclaw update` deveria detectar systemd system service

CLI assume install single-user (homebrew/asdf). Servidores em produção quase sempre usam system service pra ter `Restart=on-failure`, dependências corretas (`After=network.target`), e MemoryHigh/Max via cgroup. Vale abrir issue upstream em `openclaw/openclaw`.

### 2. `plugins.allow` deveria preservar plugins não-bundled custom no upgrade

5.20 acrescentou `graph-memory` na lista de "plugins disabled (not in allowlist)" silenciosamente — sem migration helper. Ideal: `openclaw update` detectar entries em `plugins.entries` que não estão em `plugins.allow` e prompt pra adicionar (ou auto-adicionar com warning).

### 3. graph-memory poderia ser refatorado pro SDK 5.18 `defineToolPlugin`

Lesson `[[2026-05-05-openclaw-v5.4-graph-memory-build-required]]` já apontou fragilidade do plugin. Refatorar pra usar o SDK novo reduziria o blast radius dos endurecimentos de discovery (cada upgrade testa um caminho de fallback diferente).
