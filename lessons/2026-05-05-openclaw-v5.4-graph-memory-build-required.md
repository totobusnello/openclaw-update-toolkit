# OpenClaw v2026.5.4 — Plugins `origin: "global"` exigem `dist/` compilado pré-upgrade

## TL;DR

Upgrade `2026.5.3-1 → 2026.5.4` parecia patch incremental sem cutover estrutural (96 extensions bundled idênticas, sem novo plugin externalization, sem mudança de schema). Phase 2 (atomic swap) completou em ~30s, watch loop 5min limpo, gateway healthy. **MAS** Phase 5 detectou `harness_errs=1` nos últimos 40s e o gateway emitiu silenciosamente:

```
[context-engine] Context engine "graph-memory" is not registered; falling back to default engine "legacy".
```

**Root cause:** `graph-memory` (plugin custom em `/root/.openclaw/extensions/graph-memory/`) tinha `package.json` com `main: "index.ts"` e nenhum `dist/index.js` compilado. Pré-5.4, o discovery loader tolerava plugins `origin: "global"` apontando direto pra `.ts` via jiti fallback. **5.4 endureceu**: rejeita plugins externos sem `./dist/index.{js,mjs,cjs}` ou `index.{js,mjs,cjs}` adjacente. Plugin foi DROPPED do registry (count `95→94`), context-engine caiu para `"legacy"`, recall degradado mas gateway estável.

Fix forward: `bun build ./index.ts --outdir=./dist --target=node --format=esm --packages=external` + atualizar `package.json` `main` e `openclaw.extensions[0]` apontando para `./dist/index.js` + restart. Total ~3min.

**Invariante nova (I-build-required):** todo plugin `origin: "global"` (instalado fora do bundle, em `~/.openclaw/extensions/<name>/` ou `~/.openclaw/npm/node_modules/@openclaw/<name>/`) precisa ter saída JS compilada antes de qualquer upgrade pra 5.4+. Validar pré-flight via:

```bash
for plugin_dir in /root/.openclaw/extensions/*/ /root/.openclaw/npm/node_modules/@openclaw/*/; do
  [ -d "$plugin_dir" ] || continue
  name=$(basename "$plugin_dir")
  has_dist=$(ls "$plugin_dir"/dist/index.{js,mjs,cjs} 2>/dev/null | head -1)
  has_root=$(ls "$plugin_dir"/index.{js,mjs,cjs} 2>/dev/null | head -1)
  if [ -z "$has_dist" ] && [ -z "$has_root" ]; then
    echo "MISSING DIST: $name (path=$plugin_dir)"
  fi
done
```

Qualquer match de "MISSING DIST" → bloquear upgrade até compilar.

## Por que aconteceu

### Estado pré-5.4 do plugin

```
/root/.openclaw/extensions/graph-memory/
├─ index.ts                                    ← 34KB source TypeScript (entry)
├─ openclaw.plugin.json                        ← (não declarava entry — tudo null)
├─ package.json
│   ├── "main": "index.ts"                     ← 5.3 OK; 5.4 REJEITA
│   ├── "openclaw.extensions": ["./index.ts"]  ← 5.3 OK; 5.4 REJEITA
│   └── "scripts.build": "tsc"
├─ tsconfig.json
│   ├── "noEmit": true                         ← typecheck-only, nunca emitia dist/
│   └── "include": ["src/**", "test/**", "index.ts"]
├─ src/                                        ← módulos internos (.ts)
├─ node_modules/                               ← 435 deps instaladas
└─ (NO dist/, NO compiled JS anywhere)
```

Plugin foi originalmente instalado em **2026-04-19** (data de criação do dir). Em 2026.4.X o gateway tinha source-transform fallback (jiti) que tolerava plugins externos apontando pra `.ts`. A pessoa que escreveu o plugin nunca compilou — confiou no jiti fallback.

### O que 5.4 mudou

Release notes 2026.5.4 (relevant snippets):

> **Plugins/discovery:** ignore managed npm plugin packages that only expose TypeScript source entries without compiled runtime output, so stale/broken installs cannot hide a working bundled or reinstallable channel plugin during setup.

> **Plugins/discovery:** demote the source-only TypeScript runtime check on already-installed `origin: "global"` plugin packages from a config-blocking error to a warning and let the runtime fall through to the TypeScript source via jiti, so a single broken installed package no longer blocks `plugins install` for unrelated plugins.

A leitura combinada parece dizer "demoted to warning, jiti still works" — **mas o comportamento empírico é que o plugin é dropped do registry quando NENHUMA saída JS existe**. Pode ser interpretação literal: "demote source-only" se aplica a packages que já tem dist mas com `.ts` source-only nele; plugins com APENAS `.ts` na raiz (sem qualquer `.js`/`.mjs`/`.cjs`) são rejeitados completamente.

Empíricamente:
- Plugin loaded em 5.3 ✓
- Plugin loaded em 5.3-1 ✓
- Plugin dropped em 5.4 ✗

### Por que não capturamos no staging

Phase 1 staging (dry-run) gera workspace isolado em `/tmp/openclaw-staging-workspace/` com config minimal. Plugin discovery do staging **não toca** `/root/.openclaw/extensions/` (escopo prod). Por isso o smoke test do staging passou sem detectar — staging não testa plugin discovery dos plugins instalados em prod.

## Fix forward aplicado

### Step 1 — Backup originais

```bash
cd /root/.openclaw/extensions/graph-memory
cp package.json package.json.bak-pre-5.4-build
cp openclaw.plugin.json openclaw.plugin.json.bak-pre-5.4-build
```

### Step 2 — Build via bun (não tsc)

`tsc` falhou:
- `tsconfig.json` tem `noEmit: true` → não emite arquivos
- `include` puxa `test/**` que importa `vitest` (não instalado em runtime) → erros bloqueiam compile

`bun build` funcionou:
```bash
bun build ./index.ts \
  --outdir=./dist \
  --target=node \
  --format=esm \
  --packages=external
# Bundled 14 modules in 6ms — 96.24 KB
```

**Crítico:** `--packages=external` (NÃO `--external "*"`). A diferença:
- `--external "*"` externaliza TUDO incluindo imports relativos (`./src/store/db.ts`) → quebra com `ERR_MODULE_NOT_FOUND` em runtime
- `--packages=external` externaliza apenas pacotes do `package.json` (node_modules); imports relativos são bundled

### Step 3 — Apontar package.json pro dist

```bash
jq '.main = "./dist/index.js" | .openclaw.extensions = ["./dist/index.js"]' \
  package.json > package.json.tmp && mv package.json.tmp package.json
```

### Step 4 — Restart gateway

```bash
systemctl restart openclaw-gateway
sleep 8
journalctl -u openclaw-gateway --since "20 sec ago" | grep graph-memory
```

Resultado:
```
[plugins] [graph-memory] ready | db=/root/.openclaw/graph-memory.db | provider=gemini | model=gemini-2.5-flash-lite
[plugins] [graph-memory] vector search ready
[gateway] http server listening (11 plugins: anthropic, discord, google, graph-memory, ...)
```

### Step 5 — Validar plugins list
```bash
openclaw plugins list --json | jq '.plugins[] | select(.id=="graph-memory") | {enabled, status, source}'
# {"enabled": true, "status": "loaded", "source": "/root/.openclaw/extensions/graph-memory/dist/index.js"}
openclaw plugins list --json | jq '.diagnostics[]? | select(.pluginId=="graph-memory")'
# (vazio — sem warnings)
```

## Side-effect: warning não-fatal `contracts.tools`

Pós-fix, gateway emitiu 4× durante startup:
```
[gateway] [plugins] plugin must declare contracts.tools before registering agent tools
  (plugin=graph-memory, source=/root/.openclaw/extensions/graph-memory/dist/index.js)
```

**Causa:** SDK 5.4 introduziu requisito de plugins declararem `contracts.tools` no manifest antes de chamar `registerAgentTools()` no runtime. Plugin `graph-memory` v1.5.8 foi escrito pra SDK 4.x e ainda não migrou.

**Impacto:** plugin loaded e funcional (db, vector search, recall, embedding, extraction) — apenas as 4 ferramentas que ele expõe ao agent (`graph_recall`, `graph_search`, `graph_save`, `graph_top_nodes`) **não auto-registram**. Active Memory recall via context-engine continua funcionando porque usa entrypoint diferente.

**Tarefa pendente:** atualizar `openclaw.plugin.json` ou `package.json` do graph-memory pra declarar `contracts.tools: [...]`. Não-bloqueante; vai pra TODO sem prazo crítico.

## Mitigação durável — 4 ações

### 1. Pré-flight check no orchestrator

Adicionar em `infra/scripts/upgrade-zero-downtime.sh` Phase 0 (pre-flight):

```bash
# 0g. Validate origin=global plugins have compiled runtime output (5.4+ requirement)
echo "[0g] Checking compiled runtime output for origin=global plugins..."
MISSING_DIST=()
for plugin_dir in /root/.openclaw/extensions/*/ /root/.openclaw/npm/node_modules/@openclaw/*/; do
  [ -d "$plugin_dir" ] || continue
  name=$(basename "$plugin_dir")
  if [ ! -f "$plugin_dir/dist/index.js" ] && [ ! -f "$plugin_dir/dist/index.mjs" ] && \
     [ ! -f "$plugin_dir/dist/index.cjs" ] && [ ! -f "$plugin_dir/index.js" ] && \
     [ ! -f "$plugin_dir/index.mjs" ] && [ ! -f "$plugin_dir/index.cjs" ]; then
    MISSING_DIST+=("$name@$plugin_dir")
  fi
done

if [ ${#MISSING_DIST[@]} -gt 0 ]; then
  echo "    ERROR: ${#MISSING_DIST[@]} plugin(s) missing compiled runtime output:"
  printf '      - %s\n' "${MISSING_DIST[@]}"
  echo ""
  echo "    Plugin discovery in 5.4+ rejects external plugins without dist/index.{js,mjs,cjs} or index.{js,mjs,cjs}."
  echo "    Compile with: cd <plugin_dir> && bun build ./index.ts --outdir=./dist --target=node --format=esm --packages=external"
  echo "    Then update package.json main + openclaw.extensions[0] to './dist/index.js'."
  exit 8
fi
echo "    All origin=global plugins have compiled runtime output — OK"
```

### 2. Adicionar invariante em `CLAUDE.md` regra #2.X

Nova regra (na próxima edição de `CLAUDE.md`):

> **2.3 Origin=global plugins precisam de dist/ compilado (5.4+)**
> 
> Plugin discovery em OpenClaw 5.4+ rejeita plugins `origin: "global"` (instalados em `/root/.openclaw/extensions/<name>/` ou `/root/.openclaw/npm/node_modules/@openclaw/<name>/`) que apontam pra `.ts` source sem `.js` compilado adjacente.
> 
> Sintoma: plugin sumido de `openclaw plugins list --json`, log `[context-engine] Context engine "<name>" is not registered; falling back to default engine "legacy".`, diagnostic `installed plugin package requires compiled runtime output for TypeScript entry`.
> 
> Pré-flight obrigatório: rodar check da Mitigação #1 antes de qualquer upgrade pra 5.4+.

### 3. Documentar build correto pros plugins custom

Para qualquer plugin futuro escrito em TypeScript:

```bash
# Build correto (bun, ESM, externals só de packages):
bun build ./index.ts --outdir=./dist --target=node --format=esm --packages=external

# package.json correto:
{
  "main": "./dist/index.js",
  "openclaw": {
    "extensions": ["./dist/index.js"]
  }
}
```

Não usar `--external "*"` (quebra imports relativos).

## Por que falhamos em prever

1. **Release notes ambíguos:** "demote source-only TypeScript runtime check to warning" sugeria plugin continuaria carregável. Empírico mostra que sem QUALQUER `.js`, plugin é dropped completamente.
2. **Staging não cobre prod plugins:** Phase 1 do orchestrator usa workspace isolado e config minimal — não toca `/root/.openclaw/extensions/`. Smoke test não percebia.
3. **Plugin nunca foi compilado desde 2026-04-19:** confiou em jiti fallback, ninguém percebeu que era dependência frágil.
4. **Plano v5.4 mencionava o risco mas não o pre-flight:** linha "Plugins/loader native fast path expõe bug em plugin instalado" estava no plano em "Riscos Conhecidos", mas só como observação, não como gate de pre-flight.

## Reconnaissance pra futuras releases

Adicionar ao prompt do agent reconnaissance que faz multi-agent review pré-upgrade:

> "Verificar release notes por menção a `Plugins/discovery`, `compiled runtime output`, `runtimeExtensions`, `source-transform`, `jiti`, `package-boundary`. Se houver, listar todos os plugins `origin: "global"` em `/root/.openclaw/extensions/` e `/root/.openclaw/npm/node_modules/@openclaw/` e validar que cada um tem `dist/index.{js,mjs,cjs}` ou `index.{js,mjs,cjs}` compilado."
